# Configuring the ChatGPT Action

After the gateway is reachable through public HTTPS, connect it to a custom GPT by importing the gateway's generated OpenAPI schema.

## Before opening the GPT editor

Verify all of the following first:

- the gateway is reachable from outside your home LAN;
- the public hostname uses a trusted HTTPS certificate;
- the public endpoint uses standard HTTPS port `443`;
- `PUBLIC_BASE_URL` exactly matches the public origin;
- `/openapi.json` returns valid JSON;
- the gateway is still using a deliberately small policy;
- first-time testing is performed with `READ_ONLY=true`.

Example:

```env
PUBLIC_BASE_URL=https://ha-gateway.example.com
```

Then verify:

```text
https://ha-gateway.example.com/health
https://ha-gateway.example.com/openapi.json
```

## Import the Action schema

In the custom GPT editor, add an Action and import:

```text
https://ha-gateway.example.com/openapi.json
```

The schema is generated by the running gateway, so it reflects the current gateway API rather than a manually maintained static copy.

If URL import is unavailable or does not respond, open `/openapi.json` in a browser and paste the complete JSON schema into the Action editor.

Do not replace the schema's server origin with a different hostname or non-standard port.

## Configure authentication

Use HTTP Bearer authentication with:

```text
GATEWAY_WRITE_API_KEY
```

for a new installation.

The write key has both read and write scope because the GPT must discover entities, states, services, and service contracts before it can safely act.

Do **not** use:

```text
HOME_ASSISTANT_TOKEN
```

as the Action credential. The Home Assistant token belongs only on the gateway host.

`GATEWAY_API_KEY` remains available for backward compatibility, but separate read/write gateway credentials are preferred for new deployments.

## Recommended GPT behavior

The GPT should follow a discover-before-act workflow:

1. identify the intended Home Assistant entity;
2. read its current state and capabilities when needed;
3. discover the relevant Home Assistant service;
4. read the live service contract for parameterized commands;
5. call the service only for explicit allowed `entity_id` values;
6. verify state again after a write when verification is useful.

This is particularly important for climate, media, cover, light-color, fan, TTS, and other parameterized services.

## Multi-step requests

When one clear request needs several related Home Assistant services, the GPT can use the ordered batch endpoint.

Example use case:

```text
Set the bedroom air conditioner to cool mode at 25 °C with medium fan speed.
```

The GPT should first retrieve the service contract for each required service, then submit one ordered batch.

A batch:

- validates all calls before the first write;
- executes calls sequentially;
- stops on the first Home Assistant error;
- cannot roll back an earlier call that Home Assistant already completed.

Do not use batches for unrelated or ambiguous changes.

## Long-running actions

If reviewed automation or script domains are configured for asynchronous dispatch, a service call may return HTTP `202` with a dispatch ID.

The GPT should report this as **started or queued**, not completed.

It can query the dispatch-status endpoint later when the user needs eventual gateway-side status.

## Administration actions

The separate administration endpoint is disabled by default.

If the gateway administrator explicitly enables it and adds exact actions to `ADMIN_ALLOWED_ACTIONS`, the GPT may invoke only those listed maintenance actions.

Examples can include:

- Home Assistant configuration check;
- selected reload operations;
- Home Assistant restart.

The GPT should never assume an administration action is available merely because Home Assistant supports it.

## Recommended first test sequence

Keep `READ_ONLY=true` and test in this order:

1. ask the GPT to check gateway health;
2. ask it to list allowed light entities;
3. ask it to list allowed switch entities;
4. read one harmless device state;
5. retrieve one service contract;
6. attempt a write and confirm that read-only mode blocks it.

Then configure an exact `ALLOWED_ENTITIES` list, set `READ_ONLY=false`, restart the gateway, and test one harmless on/off device while physically observing it.

## Common mistakes

### Using the Home Assistant token in ChatGPT

Wrong. The GPT receives only a gateway credential.

### Importing a local URL

A GPT Action cannot use `http://localhost:8787/openapi.json` on your private host. Use the public HTTPS origin.

### Using a non-standard public port

Prefer standard HTTPS port `443`. Keep `PUBLIC_BASE_URL` equal to the imported schema origin.

### Broadening permissions to fix a failed command

Do not immediately add broad domains or many entities. First identify the exact entity, current state, service, and service contract.

### Treating HTTP 202 as completion

`202` means asynchronous processing started. It is not final proof that the Home Assistant action finished.
